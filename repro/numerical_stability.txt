Frozen C51 evaluation: numerical stability (2026-10-08)

IMPLEMENTATION
New frozen evaluations use stable_float64_v1 in the shared DeepRLController.
The original network produces float32 logits. Softmax is recomputed from those
logits in float64, and E[Z - Z_min] is accumulated in float64 to rank actions.
The action mask is applied before argmax. Exact ties retain the first-index rule;
no epsilon tolerance, action perturbation or outcome-dependent choice is added.

The separate _q_values_from_net still returns the original unshifted E[Z] for
heatmaps, logging and training targets. Training action selection takes the
unchanged original calculation whenever enable_learning=True. Neither checkpoint
weights nor C51 training losses are changed. This implementation needs no retraining.
The FIFO-preservation intervention is separate and is NOT installed by this change.

ENVIRONMENT
For supported new runs use Python 3.13.12, requirements-tested.txt, macOS arm64,
CPU, one numerical thread. evaluate_paper.py checks config/evaluation_environment.json
and records versions, build, numerical mode and device with each evaluation.
An unvalidated environment is rejected unless --allow-environment-mismatch is
explicitly supplied for a compatibility experiment. Passing fixed-state tests is
useful evidence, not a claim of bitwise reproducibility on arbitrary platforms.

Run `make check-numerics` after a dependency change. Before accepting a new
reference environment, also run the full regression and compare representative
complete trajectories. Do not merely edit the expected actions to make tests pass.

TESTS
repro/verify_numerical_stability.py exercises the real B/500128 first divergent
state (event 18020), exact ties, support translation, A/B/C masked actions,
frozen weights, training isolation and environment mismatch rejection.
Use --full-episode for the complete 500000-event random-persistence episode,
with 10000 warmup events. Expected stable result: PnL 14.90, terminal inventory -1,
mean absolute inventory 0.828398, time at limits 0.000008. No action is forced.
The expected action arrays come from the independently archived frontier helper,
not from the new selector. The fixed-state suite is also run under PyTorch 2.5.1.

HISTORICAL REPRODUCTION
legacy_float32 is an explicit control, implemented by the unchanged controller
archived at data/paper/numerical_regression/legacy_controller.py. Its hash remains
6607491ccbf645256f291106b19bb7f2c8e6d802d93876c12f63daabd562abde.
The legacy frontier evaluator, historical A recovery, and illustrative-trajectory
rerun checks load this source explicitly. Historical source hashes and outcomes
are preserved; new results are never presented as the original computation.

WHAT NEEDS REEVALUATION
- The selected 10000-seed frontier already used this stable ranking formula;
  moving it into the common controller does not itself require another campaign.
- GLFT/naive-only simulations, calibration and analytical curves do not use C51
  action ranking and need no repeat for this numerical change.
- Value-function heatmaps use the unchanged unshifted Q calculation. Their arrays
  are checked against the existing archive; no new episode campaign is needed.
- Old A/B/C trajectory, persistence/asymmetry, recovery and stress evaluations
  that used float32 ranking can produce different actions. Quantify that effect
  with paired, newly executed original/stable evaluations before deciding which
  published result sets to replace. Frozen weights are sufficient for those runs.
- The independent regime pilot already compares original vs stable+FIFO using
  its own frozen source snapshot. It continues unchanged. Because it combines
  two interventions, an isolated numerical comparison may be needed for attribution.
  This code integration does not automatically replace paper or slide figures.
